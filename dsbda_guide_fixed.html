import pandas as pd

# ── STEP 1: Load Dataset ─────────────────────
df = pd.read_csv("autodata.csv")

df.head()

df.info()
df.describe()

# ── STEP 4: Fill Missing Values ──────────────
# Replace NaN in numeric columns with mean
for col in ['stroke', 'horsepower', 'peak-rpm']:
    if col in df.columns:
        df[col] = pd.to_numeric(df[col], errors='coerce')
        df[col].fillna(df[col].mean(), inplace=True)

# Replace NaN in categorical with mode
if 'num-of-doors' in df.columns:
    df['num-of-doors'].fillna(df['num-of-doors'].mode()[0], inplace=True)

print("\nAfter cleaning — Null values:")
print(df.isnull().sum().sum())

# ── STEP 5: Data Normalization ────────────────
for col in ['length', 'width', 'height']:
    if col in df.columns:
        df[col] = df[col] / df[col].max()

print("\nNormalized length/width/height:")
print(df[['length', 'width', 'height']].head())

# ── STEP 6: Dummy Variables (Encoding) ────────
if 'aspiration' in df.columns:
    dummy = pd.get_dummies(df['aspiration'])
    df = pd.concat([df, dummy], axis=1)
    df.drop('aspiration', axis=1, inplace=True)
    print("\nDummy encoded aspiration — first 5 rows:")
    print(df[dummy.columns].head())

# ── STEP 7: Binning (Bonus) ───────────────────
if 'horsepower' in df.columns:
    df['horsepower'] = df['horsepower'].astype(float)
    bins = np.linspace(df['horsepower'].min(), df['horsepower'].max(), 4)
    df['hp-binned'] = pd.cut(df['horsepower'], bins,
                              labels=['Low', 'Medium', 'High'],
                              include_lowest=True)
    print("\nHorsepower bins:")
    print(df['hp-binned'].value_counts())

Data wrangling (also called data munging) is the process of cleaning, transforming, and mapping raw data into a more usable format for analysis. It includes handling missing values, converting data types, normalizing, and encoding variables.
isnull() returns True where value is NaN/None (missing). notnull() returns True where value is present. Both return boolean DataFrames. We use isnull().sum() to count missing values per column.
Normalization scales values to a standard range (usually 0 to 1). We normalize to prevent features with large ranges from dominating ML algorithms. Example: df['length'] = df['length'] / df['length'].max() scales to 0–1.
Dummy variables convert categorical text data into numerical binary (0 or 1) format. ML algorithms can't process text, only numbers. pd.get_dummies() creates one column per category. Example: 'aspiration' with 'std'/'turbo' becomes two 0/1 columns.
Binning is grouping continuous numeric data into discrete categories (bins). Example: horsepower values 48–262 grouped into Low/Medium/High bins using pd.cut(). It simplifies analysis and reduces noise.
Two main approaches: 1) Drop — use df.dropna() to remove rows/columns with missing values. 2) Replace — use df.fillna(mean) for numeric columns, df.fillna(mode()[0]) for categorical. We prefer replacing to avoid losing data.

import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import seaborn as sns

# ── STEP 1: Create Dataset ────────────────────
np.random.seed(42)
data = {
    'Name': ['Alice','Bob','Carol','Dave','Eve',
              'Frank','Grace','Hank','Ivy','Jack'],
    'Math': [85, 90, None, 78, 92, 200, 88, 75, None, 82],
    'Science': [78, 88, 92, None, 85, 90, -5, 80, 87, 91],
    'English': [90, 82, 88, 76, 94, 89, 83, None, 91, 77],
    'Grade': ['A','A','B','B','A','A','B','C','A','B']
}
df = pd.DataFrame(data)
print("Original Dataset:")
print(df)

# ── STEP 2: Scan for Missing Values ──────────
print("\nMissing Values:")
print(df.isnull().sum())

# Fill missing with column mean
for col in ['Math', 'Science', 'English']:
    df[col].fillna(df[col].mean(), inplace=True)

print("\nAfter filling missing values:")
print(df.isnull().sum())

# ── STEP 3: Visualize Outliers (Boxplot) ─────
print("\nBoxplot — detecting outliers:")
plt.figure(figsize=(10,4))
for i, col in enumerate(['Math', 'Science', 'English']):
    plt.subplot(1, 3, i+1)
    plt.boxplot(df[col])
    plt.title(col)
plt.tight_layout()
plt.show()

# ── STEP 4: Handle Outliers (IQR Method) ─────
def remove_outliers_iqr(df, col):
    Q1 = df[col].quantile(0.25)
    Q3 = df[col].quantile(0.75)
    IQR = Q3 - Q1
    lower = Q1 - 1.5 * IQR
    upper = Q3 + 1.5 * IQR
    print(f"  {col}: lower={lower:.2f}, upper={upper:.2f}")
    # Cap outliers instead of dropping
    df[col] = df[col].clip(lower, upper)
    return df

print("\nHandling outliers using IQR capping:")
for col in ['Math', 'Science', 'English']:
    df = remove_outliers_iqr(df, col)

# ── STEP 5: Data Transformation (Log) ────────
# Apply log transform to reduce skewness
df['Math_log'] = np.log(df['Math'] + 1)
print("\nLog transformed Math column (first 5):")
print(df[['Math', 'Math_log']].head())

# ── STEP 6: Final Statistics ──────────────────
print("\nFinal Dataset Statistics:")
print(df.describe())

print("\n✓ Assignment 2 complete")

An outlier is a data point that significantly differs from other observations. In our dataset, Math=200 and Science=-5 are outliers as they are impossible scores. Outliers can skew analysis and need to be detected and handled.
IQR (Interquartile Range) = Q3 - Q1. Any value below Q1 - 1.5×IQR or above Q3 + 1.5×IQR is an outlier. We either drop those rows or cap them (clip to boundary). IQR is robust because it ignores extreme values when computing boundaries.
Data transformation converts values to a new scale/distribution. Log transform (np.log(x+1)) is applied to: reduce right-skewness, convert multiplicative relationships to additive, compress wide ranges. The +1 avoids log(0) error.
Skewness measures asymmetry in a distribution. Right-skewed: long tail on right, mean > median (common in income data). Left-skewed: long tail on left. Log transform reduces right skewness and makes data more normally distributed.

Mean: arithmetic average = sum/count. Affected by outliers. Median: middle value when sorted. Robust to outliers. Mode: most frequently occurring value. For categorical data, mode is the only applicable measure of central tendency.

Linear Regression is a supervised ML algorithm that models the relationship between a dependent variable (y) and one or more independent variables (X) as a straight line: y = mX + c. Used for predicting continuous values like house prices.
R² (R-squared) measures how well the model explains variance in the target variable. Value between 0 and 1. R²=1 means perfect prediction. R²=0.67 means model explains 67% of variance. Higher is better.
We split data into training set (80%) to teach the model, and test set (20%) to evaluate on unseen data. This checks if model generalizes well. Without test split, we can't know if model memorized data (overfitting).
MSE (Mean Squared Error) = average of squared differences between actual and predicted values. RMSE = √MSE — in same units as target variable. Lower MSE/RMSE = better model. RMSE of 3 means predictions are off by ~$3000 on average.
StandardScaler normalizes features to zero mean and unit variance. Without scaling, features with large values (like price) dominate those with small values (like rooms). Scaling ensures all features contribute equally to the model.

Logistic Regression is a classification algorithm (despite the name). It predicts the probability (0 to 1) of a binary outcome using the sigmoid function. Output > 0.5 = class 1, ≤ 0.5 = class 0. Used for yes/no, spam/not spam decisions.
TP (True Positive): Predicted 1, Actual 1 ✓
TN (True Negative): Predicted 0, Actual 0 ✓
FP (False Positive): Predicted 1, Actual 0 ✗ (Type I error)
FN (False Negative): Predicted 0, Actual 1 ✗ (Type II error)
Precision = TP/(TP+FP) — of all predicted positives, how many were actually positive? (quality of positive predictions)
Recall = TP/(TP+FN) — of all actual positives, how many did we catch? (completeness). High recall is important in medical diagnosis.
F1 = 2 × (Precision × Recall) / (Precision + Recall). It's the harmonic mean of precision and recall. Useful when classes are imbalanced. A balanced measure when you care about both false positives and false negatives equally.
Linear Regression: predicts continuous values (house price). Output: any number. Logistic Regression: predicts binary categories (0 or 1). Output: probability 0–1 via sigmoid function. Linear uses MSE loss, Logistic uses cross-entropy loss.

Naive Bayes is a probabilistic classifier based on Bayes' Theorem. "Naive" because it assumes all features are independent of each other (which is rarely true but works well in practice). P(class|features) ∝ P(features|class) × P(class).
Gaussian Naive Bayes assumes feature values follow a Gaussian (normal) distribution within each class. It estimates mean and variance for each feature per class. Used for continuous numeric features like sepal length and petal width.
P(A|B) = P(B|A) × P(A) / P(B). In classification: P(class|data) = P(data|class) × P(class) / P(data). P(class) is prior probability. P(data|class) is likelihood. P(class|data) is posterior — this is what we maximize to predict class.
It's fast, simple, requires little training data, handles multi-class naturally, and works well on high-dimensional data. It performs surprisingly well despite the independence assumption. Good for text classification, spam filtering, and medical diagnosis.

from nltk import word_tokenize, sent_tokenize, pos_tag
from nltk.corpus import stopwords
from nltk.stem import PorterStemmer, WordNetLemmatizer
from sklearn.feature_extraction.text import TfidfVectorizer
import pandas as pd

# ── Sample Document ───────────────────────────
text = """
Real madrid is set to win the UCL for the season.
Benzema might win Balon dor.
Salah might be the runner up.
"""

# ── STEP 1: Tokenization ─────────────────────
print("=== SENTENCE TOKENIZATION ===")
sentences = sent_tokenize(text)
print(sentences)

print("\n=== WORD TOKENIZATION ===")
words = word_tokenize(text)
print(words)

# ── STEP 2: Lowercase ────────────────────────
words_lower = [w.lower() for w in words]
print("\n=== LOWERCASE TOKENS ===")
print(words_lower)

# ── STEP 3: Stop Word Removal ────────────────
stop_words = set(stopwords.words('english'))
filtered = [w for w in words_lower if w.isalpha() and w not in stop_words]
print("\n=== AFTER STOP WORD REMOVAL ===")
print(filtered)

# ── STEP 4: Stemming ─────────────────────────
ps = PorterStemmer()
stemmed = [ps.stem(w) for w in filtered]
print("\n=== STEMMED WORDS ===")
print(stemmed)

# ── STEP 5: Lemmatization ────────────────────
lemmatizer = WordNetLemmatizer()
lemmatized = [lemmatizer.lemmatize(w) for w in filtered]
print("\n=== LEMMATIZED WORDS ===")
print(lemmatized)

# ── STEP 6: POS Tagging ──────────────────────
print("\n=== POS TAGGING ===")
pos_tags = pos_tag(filtered)
print(pos_tags)

# ── STEP 7: TF-IDF ───────────────────────────
print("\n=== TF-IDF REPRESENTATION ===")
docs = [
    "Real madrid is set to win the UCL for the season",
    "Benzema might win Balon dor",
    "Salah might be the runner up"
]
vectorizer = TfidfVectorizer()
tfidf_matrix = vectorizer.fit_transform(docs)
tfidf_df = pd.DataFrame(
    tfidf_matrix.toarray(),
    columns=vectorizer.get_feature_names_out()
)
print(tfidf_df.round(3))

print("\n✓ Assignment 7 complete")

Tokenization is splitting text into smaller units called tokens. Sentence tokenization: splits paragraph into sentences using punctuation. Word tokenization: splits sentences into individual words. First step in any NLP pipeline.
Stemming: cuts word to its root form using rules — "running" → "run", "better" → "bett" (may not be a real word). Fast but crude. Lemmatization: converts to base dictionary form using vocabulary — "better" → "good", "running" → "run". Slower but accurate.
Stop words are common words that carry little meaning for analysis — "is", "the", "a", "and", "for". We remove them to focus on meaningful words. NLTK has a pre-built list of 179 English stop words accessible via stopwords.words('english').
Part-of-Speech tagging labels each word with its grammatical role: NN=noun, VB=verb, JJ=adjective, DT=determiner, etc. Used in parsing, named entity recognition. Example: "win"→VB, "madrid"→NN, "real"→JJ.
TF (Term Frequency) = how often word appears in a document. IDF (Inverse Document Frequency) = penalizes words that appear in many documents (common but not distinctive). TF-IDF = TF × IDF. High score = word is frequent in one doc but rare in others — distinctive word.

import java.io.IOException;
import java.util.StringTokenizer;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.IntWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;

public class WordCount {

    // ── MAPPER CLASS ───────────────────────────────
    // Reads each line, splits into words, emits (word, 1)
    public static class TokenizerMapper
            extends Mapper<Object, Text, Text, IntWritable> {

        private final static IntWritable one = new IntWritable(1);
        private Text word = new Text();

        public void map(Object key, Text value, Context context)
                throws IOException, InterruptedException {
            // Split each line into tokens (words)
            StringTokenizer itr = new StringTokenizer(value.toString());
            while (itr.hasMoreTokens()) {
                word.set(itr.nextToken());
                // Emit key-value pair: (word, 1)
                context.write(word, one);
            }
        }
    }

    // ── REDUCER CLASS ──────────────────────────────
    // Receives (word, [1,1,1,...]) and sums up counts
    public static class IntSumReducer
            extends Reducer<Text, IntWritable, Text, IntWritable> {

        private IntWritable result = new IntWritable();

        public void reduce(Text key, Iterable<IntWritable> values,
                Context context)
                throws IOException, InterruptedException {
            int sum = 0;
            for (IntWritable val : values) {
                sum += val.get(); // Sum all 1s for this word
            }
            result.set(sum);
            context.write(key, result); // Emit: (word, total_count)
        }
    }

    // ── DRIVER / MAIN ──────────────────────────────
    public static void main(String[] args) throws Exception {
        Configuration conf = new Configuration();
        Job job = Job.getInstance(conf, "word count");
        job.setJarByClass(WordCount.class);
        job.setMapperClass(TokenizerMapper.class);
        job.setCombinerClass(IntSumReducer.class); // Local reducer
        job.setReducerClass(IntSumReducer.class);
        job.setOutputKeyClass(Text.class);
        job.setOutputValueClass(IntWritable.class);
        FileInputFormat.addInputPath(job, new Path(args[0]));
        FileOutputFormat.setOutputPath(job, new Path(args[1]));
        System.exit(job.waitForCompletion(true) ? 0 : 1);
    }
}
Expected Output:

Java     2
World    1
MapReduce is a programming model for processing large datasets in parallel across a cluster. Two phases: Map: transforms input into key-value pairs. Reduce: aggregates values for each key. Framework handles distribution, fault tolerance, and parallelism.
The Mapper reads each line of text, splits it into words using StringTokenizer, and emits a key-value pair (word, 1) for each word. Example: "Hello World" → (Hello,1), (World,1). Multiple mappers run in parallel on different chunks of data.
The Reducer receives all values for a given key: (word, [1,1,1,...]) and sums them up. Example: (World, [1,1,1]) → (World, 3). The framework sorts and groups mapper outputs by key before sending to reducer — this is the "shuffle and sort" phase.
A Combiner is a local reducer that runs on the mapper's machine before data is sent to the actual reducer. It reduces network traffic. In WordCount, the Combiner partially sums word counts on each node before shipping data across the network.
HDFS (Hadoop Distributed File System) is a distributed file system that stores large files split into 128MB blocks across multiple nodes. Each block is replicated 3 times for fault tolerance. NameNode manages metadata, DataNodes store actual data blocks.

import java.io.IOException;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.FloatWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.TextInputFormat;
import org.apache.hadoop.mapreduce.lib.output.TextOutputFormat;

public class WeatherDataAverage {

    // ── MAPPER ────────────────────────────────────
    // Input line: "temperature windspeed dewpoint"
    // Emits: (Temperature, temp), (WindSpeed, wind), (DewPoint, dew)
    public static class TokenizerMapper
            extends Mapper<Object, Text, Text, FloatWritable> {

        private Text category = new Text();
        private FloatWritable val = new FloatWritable();

        public void map(Object key, Text value, Context context)
                throws IOException, InterruptedException {
            String[] cols = value.toString().split(" ");
            if (cols.length < 3) return;

            category.set("Temperature");
            val.set(Float.parseFloat(cols[0]));
            context.write(category, val);

            category.set("WindSpeed");
            val.set(Float.parseFloat(cols[1]));
            context.write(category, val);

            category.set("DewPoint");
            val.set(Float.parseFloat(cols[2]));
            context.write(category, val);
        }
    }

    // ── REDUCER ───────────────────────────────────
    // Computes average for each category
    public static class FloatAverageReducer
            extends Reducer<Text, FloatWritable, Text, FloatWritable> {

        private FloatWritable result = new FloatWritable();

        public void reduce(Text key, Iterable<FloatWritable> values,
                Context context)
                throws IOException, InterruptedException {
            float sum = 0;
            int count = 0;
            for (FloatWritable a : values) {
                sum += a.get();
                count++;
            }
            result.set(sum / count); // Average
            context.write(key, result);
        }
    }

    public static void main(String[] args) throws Exception {
        Configuration conf = new Configuration();
        Job job = Job.getInstance(conf, "weather data average");
        job.setJarByClass(WeatherDataAverage.class);
        job.setMapperClass(TokenizerMapper.class);
        job.setReducerClass(FloatAverageReducer.class);
        job.setMapOutputKeyClass(Text.class);
        job.setMapOutputValueClass(FloatWritable.class);
        job.setOutputKeyClass(Text.class);
        job.setOutputValueClass(FloatWritable.class);
        job.setInputFormatClass(TextInputFormat.class);
        job.setOutputFormatClass(TextOutputFormat.class);
        TextInputFormat.addInputPath(job, new Path(args[0]));
        TextOutputFormat.setOutputPath(job, new Path(args[1]));
        System.exit(job.waitForCompletion(true) ? 0 : 1);
    }
}

WordCount uses IntWritable and counts (sums 1s). Weather uses FloatWritable and computes averages (sum/count). Mapper emits category names ("Temperature") as keys, actual float values as values. Reducer computes mean per category. Same MapReduce structure, different logic.
Temperature, wind speed, and dew point are decimal numbers (floats), not integers. Hadoop provides wrapper classes for Java primitives that implement Writable interface for serialization: IntWritable→int, FloatWritable→float, LongWritable→long, Text→String.

// Assignment B4 — Apache Spark WordCount in Scala
// Run in spark-shell: spark-shell --master local

// ── Step 1: Read input file ───────────────────
val input = sc.textFile("passage.txt")
// sc = SparkContext, automatically available in spark-shell

// ── Step 2: Split each line into words ────────
val words = input.flatMap(x => x.split(" "))
// flatMap flattens: [[Hello,World],[Java]] → [Hello,World,Java]

// ── Step 3: Map each word to (word, 1) ────────
val counts = words.map(x => (x, 1))

// ── Step 4: Reduce by key (sum counts) ────────
val reducedCounts = counts.reduceByKey((x, y) => x + y)
// Groups by word key and sums all 1s for that word

// ── Step 5: Print results ─────────────────────
reducedCounts.foreach(println)

// ── Step 6 (Optional): Save to file ──────────
reducedCounts.saveAsTextFile("output")

// ── One-liner version (elegant Scala) ─────────
sc.textFile("passage.txt")
  .flatMap(_.split(" "))
  .map((_, 1))
  .reduceByKey(_ + _)
  .foreach(println)

Apache Spark is an in-memory distributed computing framework. 100× faster than Hadoop MapReduce because it processes data in RAM instead of disk. Supports batch processing, streaming, ML (MLlib), and graph processing. Works on Scala, Python, Java, R.
RDD (Resilient Distributed Dataset) is Spark's core data abstraction. An immutable, partitioned collection of records that can be processed in parallel across a cluster. "Resilient" = fault tolerant (can recompute lost partitions from lineage). Created by sc.textFile(), sc.parallelize(), or transformations.
map(f): applies f to each element, returns one output per input. If input is a line, output is a list. flatMap(f): applies f to each element AND flattens the result. "Hello World".split() = ["Hello","World"] — flatMap unpacks this into separate elements.
reduceByKey((x,y) => x+y) groups key-value pairs by key and applies the reduce function to combine values. For WordCount: all (word, 1) pairs with same word get their 1s summed. Similar to SQL GROUP BY + SUM.
Hadoop MR: disk-based, reads/writes HDFS between stages, slow, good for ETL. Spark: in-memory, data stays in RAM, up to 100× faster for iterative algorithms (ML, graph). Spark also handles streaming and SQL natively. Both run on YARN.
